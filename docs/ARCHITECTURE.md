# Implementation notes

Glissform is a macOS app for subtle animations and quality-of-life improvements across everyday interactions. The current implementation contains Infinite Screen plus shared settings, appearance, permission presentation, and menu infrastructure. The lid sensor, capture pipeline, and projection described below belong to Infinite Screen; they are not requirements for every future experience. Additional experiences have not been implemented yet.

- **LidSensor.swift:** read-only IOKit HID access, Apple vendor/product `05ac:8104`, usage `0020:008a`, feature report 1. Whole-degree values are read on a serial worker at 30 Hz, with bounded reconnect backoff. Protocol support is undocumented.
- **ClosingMotion.swift:** gesture and threshold state, including awake reversal and startup/reset behavior. Optional pause restoration uses monotonic sensor timestamps, a one-degree min/max stability band, and a 0.5–10 second wait supported internally for tests; the app uses a fixed two seconds. Movement beyond that band resets the clock, as do invalid readings or gaps over 250 ms. Expiry deactivates the gesture and latches suppression until the lid is strictly above the trigger. Lifecycle reset clears the clock and latch; low-angle startup remains unarmed.
- **DesktopCapture.swift:** one native-resolution sRGB ScreenCaptureKit screenshot per gesture, excluding Glissform itself. No stream is started. Pixels remain in memory.
- **ScreenProjection.swift / EffectRenderer.swift:** runtime-compiled Metal projection and frost/shadow, with a fixed viewpoint approximation. Camera distance is four screen heights and eye height 1.1 screen heights, relative to the reference image plane. Every physical degree maps to one rendered degree, with no 89° fold clamp. Frost uses a normalized 5×5 binomial (Gaussian-like) kernel over interpolated mip levels. Radius grows monotonically with displayed closing progress through `(1 - exp(-3p)) / (1 - exp(-3))`, establishing the diffuse material early. A smooth vertical gradient scales its maximum support radius from 1.5% of image height at the hinge to 9% at the top (kernel standard deviation is approximately half that radius), retaining more definition so the perspective remains visible. This is visual tuning against the supplied reference stills, not a reconstruction of their original shader or timing. Shadow strength follows `p^2.2`, retaining more colour through mid-closure while keeping the full-height gradient and final top 5% black plateau. Active rendering requests the display's maximum refresh rate and pauses once settled.
- **MotionSmoothing.swift:** exact critically damped filtering for quantized angles and 100 ms boundary handoffs. Velocity is retained when response time changes; reversals discard old-direction momentum. Averaged per-degree cadence selects the response smoothly, avoiding the former fast/slow switch between one- and two-degree reports. The usual 35 ms time constant shortens above 30 degrees/second and grows for sparse readings up to 100 ms; reversals and large discontinuities use 12.5 ms. Smoothing deliberately trades some tracking delay for steadier movement. No angles are extrapolated beyond the reported target.
- **main.swift:** menu controls, settings coordination, snapshot preparation/reveal, overlay ordering and click blocking, sensor/capture coordination, and cleanup across sleep, display changes, cancellation, and quit.
- **OverlayWindow.swift:** a borderless, non-activating `NSPanel` that joins all Spaces and other applications, including native full-screen Spaces. It does not become key or main and does not hide when Glissform deactivates. This presentation is independent of the app's regular/accessory activation policy, so opening settings does not strand the effect on a desktop Space. Runtime and synthetic lifecycle checks share the same window setup.
- **SettingsWindow.swift:** native SwiftUI settings interface hosted in an AppKit window, including live sensor and permission state, persisted animation controls, and concise privacy information.

The first screenshot frame is rendered while the window is transparent. An 80 ms fade reveals it; the 100 ms angle handoff begins on the first fade tick, retaining an identity first frame instead of waiting for the entire fade. Returning to flat precedes an 80 ms exit fade. Snapshot tokens and renderer transition generations reject stale asynchronous work. The capture-source interface permits lifecycle checks to resolve synthetic screenshots after cancellation without requesting screen access.

Infinite Screen uses a frozen image viewed through a simulated moving panel. It does not track the viewer's head, intercept the lock screen, or keep the system awake.

The settings window controller switches the app to regular activation when presenting settings and to accessory activation when that window closes. The Dock entry therefore follows settings, independently of the overlay window. Closing the last window does not terminate the app; sensor, capture, menu bar, and interruption handling continue. Menu bar Settings and application reopen events present the retained window again. This uses ordinary AppKit activation policies and needs no extra permission or login helper.

The settings window opens directly on the experience page, with native controls and semantic system colors. The footer opens Privacy & About; a Back button (⌘[) returns to the experience. There is no shared logo header or segmented navigation. An original Canvas illustration projects synthetic screen contours and a MacBook lid in perspective; the illustration follows the live reading, but does not reproduce the Metal effect pixel for pixel. SettingsModel synchronizes trigger controls, enable state, live angle, permission, and runtime status. The preview card groups the illustration and threshold controls, separated by a divider. A separate pause-to-resume settings card follows below it; runtime readiness remains in the menu bar. A shared screen-access card appears above the preview only while access is missing or during a three-second confirmation after a detected grant. It remains available in Privacy & About for status and management. Authorized launches omit the main-page card; revocation restores it. The main view owns the cancellable confirmation task. The shared root measures each page’s natural height and resizes the window while retaining its top edge and 32-point bottom padding. A shared scroll view handles content above the available-screen height cap. The current angle remains above the illustration; the slider has no live-angle marker. Preview and pause settings cards share a background, corner radius, and border, with a 16-point gap. The privacy footer has reserved bottom padding. Privacy & About, also opened by the standard About Glissform menu command, shows the app name and version, the privacy-information card, and the separate access card. There is no embedded access section or divider in the privacy card and no description or text below the cards. Hardware and alpha limitations remain in README and testing documentation.

The in-window preview has local observable state and a finite SwiftUI task. It snapshots the displayed lid angle and reference plane when playback starts, then immediately begins a synthetic close/reopen cycle back to that angle, without an opening hold. Its closing target is 22° or the starting angle if already lower, so starting the preview never first opens a nearly closed illustration. It stops on request or navigation away, and never calls DesktopCapture or the overlay renderer. Reduce Motion replaces playback with a still preview and disables interpolation of the live illustration. All content surfaces are opaque and adapt to system appearance; controls use the system accent. These accessibility changes apply to the settings illustration, not to the actual desktop effect.

Settings buttons share a ButtonStyle for hover and pressed feedback; activation and cancellation remain owned by SwiftUI Button. The AppKit slider preserves system tracking and keyboard input with a solid-white thumb that changes size slightly on hover/press. The angle field includes a raised degree symbol and left-side arrow buttons, each with independent hover/pressed feedback and hold-to-repeat. A SwiftUI capsule switch keeps its thumb solid white, applies hover/press feedback to the track, matches the System Settings proportions, uses Button for activation, and exposes a native Toggle accessibility representation. The slider and switch add no outer hover surface or border; arrow highlights stay inside their own hit areas. The angle field adds an editing outline. The settings window ends field editing on an outside mouse click before forwarding that same event, so other controls still respond on the first click. Feedback overlays do not intercept input, disabled controls suppress feedback, and transitions respect Reduce Motion.

Pause restoration uses the existing return-to-flat and fade-out path, including snapshot cancellation tokens. No independent timeout can fire while sensor delivery is absent. Only the pause toggle is stored in UserDefaults; changing it restarts tracking without clearing an already-restored gesture latch. The app uses the motion model's fixed two-second default and no longer reads or writes a user-selected duration. The pause card is a single row with the shared solid-colour icon tile at 16% opacity. The menu status reports when the desktop has been restored.

SettingsDesign.swift defines the settings spacing, typography, radii, semantic surfaces, appearance-specific icon colours, and interaction timings. SettingsWindow.swift consumes those foundations and shares its card surface across the main page and About; the full-width divider is used within the Infinite Screen preview/control card. Native controls retain platform keyboard and accessibility behaviour; custom arrows use 24 × 20-point targets with a shared disabled opacity. See [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) for the component rules and deliberate optical exceptions.

IconlyIcon.swift supplies cached local SVG template images. Bold / Regular is the app default; original Outline and Bulk sets and the previous Custom mix remain available for developer comparison. Custom card variants alter only secondary opacity, not source paths. The `--dev` build flag enables the Developer menu and session-only style shortcuts; normal builds omit it. SwiftUI interface icons update without resetting feature state. `BrandIcon.swift` loads the cached 18-point `GlissformMenuBar` image from the main asset catalog. The build exports ClearDark directly from `Artwork/Glissform.icon` using Icon Composer at 1× and 2×. `scripts/make-menu-template.swift` converts luminance into alpha, preserving the original contours and wave as monochrome detail. The result is compiled as a template image set alongside the app icon. AppKit supplies the menu bar foreground colour; developer icon switching does not replace it. See [ICONLY.md](ICONLY.md) for provenance and [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) for current tokens.

The brand app icon is separate from Iconly. `Artwork/Glissform.icon` holds a shaded glass-wave PNG and native appearance definitions. Clear and tinted are derived from the same artwork. `scripts/build.sh` uses Xcode 26+ `actool` to compile the native catalog and legacy `.icns`, merges the generated icon metadata into the main bundle, updates the `.app` directory's modification date for Launch Services, and signs afterward. Presenting settings resets `NSApp.applicationIconImage` to `nil` after restoring regular activation; this restores the bundled icon rather than assigning a static bitmap, leaving macOS in control of system style selection. Privacy & About reads the application icon supplied by AppKit; this in-app image does not live-follow Finder's style changes.
