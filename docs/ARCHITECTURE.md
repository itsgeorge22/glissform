# Implementation notes

Glissform is a macOS app focused on Seamless Close. The current source includes its animation, an email feedback page, signed updates, and shared settings, appearance, permission presentation, and menu infrastructure.

## Connected displays — unreleased

`DisplayConfiguration.swift` reads the online CoreGraphics display list, including mirror followers that AppKit may omit from `NSScreen.screens`. It distinguishes a mirrored built-in display from mirrors involving only external displays. Display IDs, mirror relationships, bounds, backing pixel sizes and rotation form the topology; active/asleep availability is separate so ordinary laptop-only sleep need not invalidate an eligible cached image.

The coordinator saves `seamlessCloseExternalDisplaySupportEnabled` (default true). With support on, an active, unmirrored built-in screen is the only capture/render target; with support off, any online external display pauses the effect. Both the card and menu status explain pauses without mutating `animationEnabled`. CoreGraphics begin-reconfiguration callbacks clear screenshots, pending asynchronous work, overlays, Esc interception and connection feedback. AppKit notifications update geometry; a 300 ms quiet interval coalesces notifications before reconnecting. A separate lid-rearm gate survives sleep and sensor resets, preventing a new mid-gesture capture. Every capture presentation rechecks topology and mirror policy, including before a delayed screenshot can reveal.

A fully closed lid (at most 1°) with an external display clears the image even if the driver has not yet removed the built-in screen. External-display sleep never retains a closing image. Reopening after that session therefore shows the live desktop; awake partial reversals still use the same gesture image. No display configuration, application window placement, system sleep or locked-screen behavior is changed. Synthetic policy and coordinator checks are separate from pending physical display acceptance.

The dormant [licensing prototype](LICENSING_PREVIEW.md) uses `LicenseAccess.swift` for trial state and the `LicenseService` interface, `LicenseController.swift` for local persistence and asynchronous checkout/activation, and a loopback Python/SQLite service for simulated purchases and device slots. `LicenseController.previewsEnabled = false` disables the entry point even for flagged Dev launches: no trial starts, saved trial/key data is ignored and untouched, commerce methods do nothing, and use is unrestricted. Hidden screens and access-cancellation paths remain available for future reuse and isolated regression tests. Production payment verification and entitlement protection remain unimplemented.

- **LidSensor.swift:** read-only IOKit HID access, Apple vendor/product `05ac:8104`, usage `0020:008a`, feature report 7 for hundredths of a degree, falling back to whole-degree report 1 on unsupported hardware. A serial worker requests readings at 30 Hz while idle and 60 Hz during active gestures, with bounded reconnect backoff. Each reading carries its monotonic host acquisition time, recorded after the HID read and before main-queue delivery; the report contains no hardware timestamp. Polling frequency does not establish the sensor's actual update frequency. The fractional report worked on the development Mac, but other hardware remains unverified. Protocol support is undocumented.
- **ClosingMotion.swift:** gesture and threshold state, including awake reversal and startup/reset behavior. Optional pause restoration uses monotonic sensor timestamps, a one-degree min/max stability band, and a saved 0.5–10 second wait, defaulting to one second. Movement beyond that band resets the clock, as do invalid readings or gaps over 250 ms. Expiry deactivates the gesture and latches suppression until the lid is strictly above the trigger. Automatic starting-angle mode separately learns a 20–130° idle lid angle after its saved 0.5–10 second wait of fresh readings inside a one-degree band; the manual trigger remains the fallback until then. A learned angle overrides that trigger without changing the active gesture plane and survives lifecycle reset for the current session. When pause restoration is enabled, its expiry can adopt the paused angle while keeping the desktop-restored latch until the lid opens above the new angle. Lifecycle reset clears the clocks and latch; low-angle startup remains unarmed until a valid rest is learned or the lid opens above the fallback.
- **DesktopCapture.swift:** one sRGB ScreenCaptureKit screenshot per closing attempt, with dimensions derived from the filter's content rectangle and point-to-pixel scale, checked against the overlay drawable and returned buffer. The identified overlay window is excluded. If the hidden overlay is missing from metadata, application exclusion with explicit exceptions for other known Glissform windows prevents recursive capture while preserving settings where metadata permits. Unknown or foreign overlay ownership fails closed. A shared, generation-protected metadata cache has a 30-second lifetime; connection prewarming and a subsequent gesture can share discovery without capturing pixels. Settings presentation, activation and close invalidate the metadata, as do display/session/access changes; generation checks reject late discovery and capture results. No stream is started. Pixels remain in memory.
- **WakeOpening.swift:** numeric eligibility for reusing the closing image after sleep; it owns no pixels. The coordinator requires a completed closing screenshot and a recent 0–20° reading before arming an attempt. Duplicate wake notifications do not reset its three-second deadline. Fresh rising readings spanning at least two degrees may prepare the retained frame while more than three degrees remain below the reference. Samples more than 250 ms apart restart movement evidence before preparation and cancel pending preparation. Reversal by more than two degrees, expiry, unavailable desktop, or reaching the reference cancels a pending reveal. Once visible, ordinary reversal and pause behavior take over.
- **DesktopAvailability.swift:** preflight permission, active/awake display, console/logged-in session, frontmost application, and the optional undocumented `CGSSessionScreenIsLocked` hint. Missing session/frontmost evidence fails closed; the lock field itself is normally absent on an unlocked desktop, so its absence alone is not proof of unlock. The coordinator also listens for undocumented distributed `com.apple.screenIsLocked` / `com.apple.screenIsUnlocked` notifications and public session-switch notifications. The coordinator keeps a sleep-associated closing snapshot hidden through lock, but session deactivation clears it. This is a prototype heuristic requiring physical OS-version validation, not a public unlock guarantee or security boundary. `canBecomeVisibleWithoutLogin` remains false; no private window spaces or login helpers are used.
- **ScreenProjection.swift / EffectRenderer.swift:** runtime-compiled Metal projection and frost/shadow, with a fixed viewpoint approximation. Camera distance is four screen heights and eye height 1.1 screen heights, relative to the reference image plane. Every physical degree maps to one rendered degree, with no 89° fold clamp. `MPSImageGaussianPyramid` prepares blur levels once per screenshot; the pyramid is reused through closing and eligible wake opening. Its kernels are warmed with synthetic pixels during renderer setup. sRGB textures decode for linear-light filtering and shading, then encode into the sRGB output. Frost strength grows with displayed progress through `(1 - exp(-3p)) / (1 - exp(-3))`; a smooth vertical gradient scales the radius parameter from 1.5% of image height at the hinge to 9% at the top. A normalized 5×5 binomial reconstruction samples a finer pyramid level in 25 taps to reduce coarse mip cells visible in bright details while preserving the previous total blur variance. The pyramid and shader samples clamp their edge colors; a single smooth source-rectangle coverage mask fades all four projected image boundaries so separated taps do not form parallel dark contours when they cross an edge separately. The level follows `0.5 * log2(1 + 0.25 * radius²)` and the five sample positions on each axis are spaced by half the radius; both approach the untouched base image at zero. This is visual tuning, not a reconstruction of the supplied reference shader. Broad shadow strength follows `p^2.2` with the full-height gradient and final top 5% black plateau. A separate contact shadow is anchored to the physical top edge: at displayed closure angle `d` in degrees, its strength is `0.88 * (1 - exp(-d / 3))`, its depth is `0.035 + 0.20 * (1 - exp(-d / 22))` screen heights, and its falloff is `exp(-(y / depth)^1.6)`. The two shadows multiply transmittance. This establishes bezel depth within the first few degrees without darkening the whole screen early. Fixed 8×8 spatial dithering distributes final 8-bit rounding without temporal noise. Neighboring tiles change the row phase so each 64-pixel span covers all 64 thresholds rather than repeating a row-biased pattern; the identity frame and exact black bypass it. The shader emits opacity premultiplied in encoded sRGB for Core Animation composition through a nonopaque Metal layer, while retaining linear-light filtering and shading.
- **Screen-space finishing blur:** for nonflat visible frames, Metal renders the existing projected material into a temporary texture; Core Image flips it into the drawable's orientation and applies one even `CIGaussianBlur` on the same command buffer. A cached smooth vertical mask blends the blurred result with the original projection from 65% strength at the hinge to full strength at the top; its radius grows with displayed frost progress and scales with the selected Blur strength. The projection has uniform alpha, so blending uses the existing mask without a separate erosion pass. Up to three temporary textures are reused only when their prior GPU work has completed, and an unavailable slot falls back to the existing source-space renderer. The flat identity frame bypasses this extra pass. The drawable permits shader writes for Core Image, which may add cost even before the blur does; frame pacing and edge behavior are not guaranteed beyond the owner's local visual comparison.
- **MotionSmoothing.swift:** acquisition-timed, exact critically damped filtering for fractional or quantized angles. Ingestion advances the trajectory at each sensor timestamp; presentation-time queries evaluate it without changing sensor cadence or history. A rolling history of up to four reading intervals estimates cadence. Fractional changes use their measured size with a quarter-degree lower bound so very small steps receive steadier smoothing without unbounded lag; whole-degree changes retain their prior cadence. The response changes gradually, with a 24 ms moving-response floor and 118 ms slow-response ceiling. The initial isolated large step retains its fast response. A change under 0.08° is treated as sensor jitter; a backwards movement under about one degree must persist for 50 ms even when each fractional reading differs, while a larger reversal is accepted immediately; a sample gap over 100 ms resets that confirmation. Gesture, threshold, and sleep decisions still receive raw readings. Confirmed reversals preserve velocity and brake with a response of at most 45 ms. When incoming speed could cross a nearer target, damping is adjusted to brake before it instead of clipping position or zeroing velocity. Smoothing trades tracking delay for steadier speed and does not extrapolate future sensor targets; existing momentum may briefly continue while a reversal brakes. Manual completion continues evaluating this same filter, including new sensor samples, without replacing its position, velocity, or damping. The shared damped response also supports a separate programmatic return when the feature is disabled. Entrance and pause transitions use bounded quintic curves with compatible incoming velocity and exact endpoints.
- **main.swift:** menu controls, settings coordination, snapshot preparation/reveal, overlay ordering and click blocking, sensor/capture coordination, and cleanup across sleep, display changes, cancellation, and quit.
- **OverlayWindow.swift:** a borderless, non-activating `NSPanel` that joins all Spaces and other applications, including native full-screen Spaces. It does not become key or main and does not hide when Glissform deactivates. This presentation is independent of the app's regular/accessory activation policy, so opening settings does not strand the effect on a desktop Space. Runtime and synthetic lifecycle checks share the same window setup.
- **SettingsWindow.swift:** native SwiftUI settings interface hosted in an AppKit window, including live sensor and permission state, persisted animation controls, and concise privacy information.

During a fast close, the coordinator may request its one screenshot after a downward reading of at least 0.15° and 12°/s within three degrees above the active starting angle. The first closing frame is prepared at identity while the overlay is hidden; crossing the starting angle permits its presentation, then geometry begins a 100 ms handoff. An upward reversal of more than 0.25° or 350 ms without crossing cancels the hidden attempt, and it cannot retry early until the lid opens above the three-degree lead window. If no early capture is ready, the usual capture at the threshold remains available. This removes the old live/frozen-image entrance dissolve. Wake opening starts from the current fold and fades in over 50 ms. Manual reopening remains on `MotionSmoothing` all the way to zero. Reaching the raw starting angle requests cleanup but does not start another trajectory or stop sensor ingestion; polling remains active until completion. Recloses during this stage cancel cleanup without a new geometric handoff. The image must reach exact identity on the existing filter before its final fade. A separate `ProgrammaticReturn` is used only when disabling the feature during a gesture, and settles within 650 ms. Pause restorations use balanced 340–600 ms quintic motion according to deformation, with lower peak speed than the prior front-loaded curve. Geometry and material reach identity before a 50 ms fade exposes the live desktop. Reclosing cancels the old finish; after a pause return it uses the current rendered position and compatible velocity, while manual completion keeps the uninterrupted lid trajectory.

Assisted opening in the last 5° draws the trigger's newest lid-driven frame before takeover, then carries its visible speed and bounded display-to-display acceleration. `OpeningAssist` uses the most recent 80 ms of available upward readings, falling back to the last two meaningful readings for sparse input. The cruising speed cannot be below the entry speed or recent sensor estimate, and there is no 120°/s cap. A quintic velocity blend carries positive acceleration with at most 25% extra momentum; pre-existing negative acceleration is bounded to a small transient dip. The blend lasts up to 80 ms; a shallow fold shortens it completely rather than truncating it. The final 15% (at most 1.5°) keeps its continuous soft landing. Assisted opening, Pause and Esc share connection feedback; `.pause` covers both Pause and Esc and retains its existing return curve. For assisted opening, the rim width follows `OpeningContinuation`'s normalized time. Pause/Esc keeps the glow hidden until the rendered fold enters its final 5°, then uses normalized remaining fold (clamped to the starting fold for shallower returns). Both pass that progress through the same quintic ease, increasing width and glow opacity from zero and reaching their maximum at flat. A smooth distance field, xy / sqrt(x² + y²), joins the nearest horizontal and vertical edge distances into one continuous light field with bounded corner brightness. The approach has a Gaussian shoulder and local spill at 24% and 8% weights. At contact the shoulder widens from 42% to 54% of the spread, spill gains up to 2.5 percentage points, and an 11% Gaussian crest remains at 16% of the spread with a diffuse 38% width. There is no independent traveling crest. The intensity rises from 1 to 1.75 over the 65 ms before the scheduled click peak with quintic easing, then settles over 180 ms using (1-t)^3(1+3t). This bounded anticipation waits for audio readiness; the visible Pause/Esc glow still stays inside the final five degrees. Its target peak remains the predicted flat display frame plus the original 30 ms contact offset, rounded to the display frame clock. A late audio route moves the pulse and audible peak together; geometry and the 50 ms desktop reveal continue independently. A transmittance-power curve boosts the inner glow without restoring the removed outline; the distance field joins the corners without overlapping bright strips. Reversal cancels the pulse and settles its current intensity to the approach level over 80 ms. The maximum spread scale is 3.2% of the shorter display dimension, with the spill fading out by 2.7 times that scale; the approach shoulder is 42% of the scale. The field uses rectangular display bounds. The inspected public display APIs provide safe-area insets and rectangles, and no exact physical top-corner contour was found in this Mac's device-tree geometry; no estimated corner radius is applied. The release spans 320 ms from 30 ms before the scheduled peak; glow opacity stays full through that peak, then uses the same tapered settling curve to reach zero. Width contracts by only 45% during the release and is cleared once opacity reaches zero, avoiding a bright final squeeze. Reversal captures current intensity and opacity, cancels further brightness rise and fades over 240 ms with the same gentle width contraction. The glow remains as a translucent edge layer while the screenshot fades out. The renderer releases mouse input after that fade and completes snapshot cleanup after the glow disappears. The saved `seamlessCloseConnectionEffectEnabled` preference defaults to true and controls both outputs. When off, the coordinator skips audio preparation and the renderer suppresses glow and peak scheduling without changing geometry or screenshot fading. Live disable cancels pending playback and clears the rim; enabling takes effect at the next return. `OpeningConnectionSound` loads the PCM sample and finds its strongest frame (currently about 2.63 ms). An output-only `AVAudioEngine` starts on a separate serial queue only after the screenshot (or retained image) and hidden first frame are prepared, stays ready for that gesture, and schedules an `AVAudioPlayerNode` against host time before contact. The node’s current `outputPresentationLatency` and sample peak offset determine its render start. If startup leaves insufficient lead time, it returns the earliest attainable peak to the renderer. Generation checks discard stale startup results; reversal and lifecycle cancellation stop pending playback. Normal visual completion retires audio only after `.dataPlayedBack`, with a one-second fallback for a lost completion callback. No input node or microphone is used. The reported latency is a scheduling estimate, not a physical measurement of Bluetooth sound arrival, and already-buffered wireless output cannot be recalled.

`CAMetalDisplayLink` owns production rendering and supplies target presentation timestamps. It requests the screen's maximum refresh rate and one frame of latency; these are scheduling preferences, not guaranteed pacing. MetalKit's internal draw loop remains paused. The display link pauses at rest. Hidden first-frame preparation detaches it before acquiring a drawable; production display callbacks use only their supplied drawable. The synthetic lifecycle harness can explicitly render offscreen without competing for a display-linked drawable. Motion and shader opacity share this clock instead of separate window-alpha timers. A transparent final frame permits cleanup after GPU completion; presentation callbacks supply diagnostics and are not an unbounded prerequisite for releasing mouse access. A main-run-loop watchdog checks completion after 800 ms. Manual completion repeats that check while submitted frames have advanced geometry or opacity within the previous 250 ms, so a slow final degree is not cut off by a fixed deadline. Assisted and Pause/Esc feedback similarly extends its watchdog while frames advance, allowing the 400 ms rim retreat to finish after mouse access returns. Freshly rendered frames waiting for a scheduled pulse can extend the watchdog for at most 1.5 seconds from scheduling; stalled rendering still fails closed. Stalled completion clears on the next watchdog tick; disabled returns retain their fixed 800 ms deadline. Sleep, lock, display changes, revoked access, and quit still hide immediately. Snapshot tokens and renderer transition generations reject stale asynchronous work. The capture-source interface permits lifecycle checks to resolve synthetic screenshots after cancellation without requesting screen access.

Wake opening reuses the completed closing image and prepares its first frame at the current fold, bypassing the closing entrance handoff. `EffectRenderer.pauseSnapshot()` stops drawing and invalidates transition callbacks while retaining the same pixel buffer, CVMetalTexture wrapper, and filtered texture/mipmaps. `prepareRetainedSnapshot()` renders from those resources without invoking ScreenCaptureKit or uploading/regenerating the image. `clear()` still releases them. The coordinator separates a retained hidden image from an active snapshot; only a completed, active closing gesture with recent near-closed evidence may cross sleep. A pending/failed capture, a restored desktop after a pause, or another sleep during an opening leaves no cached wake attempt. There is no fresh-capture fallback.

Eligibility, desktop availability, permission, and sensor freshness are checked before and after GPU preparation. A 50 ms timer bounds waiting until reveal/cancellation or three seconds after the first wake. Sensor restart and display reconnection begin immediately. Display identity, frame, scale, and connected screen layout must match; real reconfiguration clears the cache, while redundant unchanged display notifications preserve it. The overlay is transparent, nonblocking, and paused during retention. Gesture completion, cancelled/skipped wake, session switch, display change, revoked access, disable/threshold changes, and quit release all image resources. Screen-access checks use the existing grant; no screenshot stream, new permission, disk image cache, or sleep assertion is created. Local unified wake logs report retention eligibility, wake, first sensor delivery, cached-frame request/preparation, reveal requests, and skips, without desktop content. Submission/readiness timestamps are not physical presentation timestamps. Opt-in `MotionTiming` and `AnimationTiming` debug diagnostics report numeric HID read counts/cost, capture metadata/pixel/preparation timings and dimensions, and drawable presentation intervals/input age; they contain no desktop pixels, titles, or captured application identities. See [TESTING.md](TESTING.md) for invocation and interpretation.

Seamless Close uses a frozen image viewed through a simulated moving panel. It does not track the viewer's head, intercept the lock screen, or keep the system awake.

Ordinary lock hints during sleep or before wake preparation preserve the hidden frame and original deadline. If lock arrives before actual sleep during a completed closing gesture at 0–20°, a one-second grace period holds the image; repeated lock hints do not extend it, and unlock without sleep or grace expiry releases it. Public session-deactivation events always clear the image. After wake, sensor samples are evaluated while locked: reaching the reference or expiry clears the cache, with no capture or reveal. Unlock does not reset the deadline or start preparation by itself. A lock during preparation or visible opening cancels that attempt completely, including asynchronous results.

Sensor health compares both the last actual reading and the most recent restart against its one-second limit. A heartbeat queued during sleep cannot treat the old timestamp as a failed restart at 0–4 ms after wake. Duplicate wake notifications do not move that restart time. This startup allowance does not mark any reading fresh: retained-frame preparation still requires real sensor samples and retains the existing 250 ms freshness and three-second wake bounds.

The settings window controller switches the app to regular activation when presenting settings and, when background running is enabled, to accessory activation when that window closes. The Dock entry therefore follows settings, independently of the menu bar icon and overlay window. Closing the last window keeps the app running only when background running is enabled; sensor, capture, menu bar (if shown), and interruption handling continue. Menu bar Settings and application reopen events present the retained window again. This uses ordinary AppKit activation policies and needs no extra permission or login helper.

The settings window opens on Seamless Close, with a persistent SwiftUI button sidebar for General, Seamless Close, Privacy & about, and Send feedback. Buttons select SettingsModel.selectedPage; changing pages does not mutate feature enable states. The sidebar handles Up/Down navigation and marks the current page as selected for accessibility. Features and More use title-case section headings, with More directly below the feature tabs. Seamless Close combines its enable row and manual angle in one card. Sidebar icon tiles remain saturated; page tiles use 12%-opacity fills and coloured symbols.

SettingsModel synchronizes manual and automatic trigger controls, the learned angle, enable states, live angle, permission, and runtime status. Seamless Close combines its enable row and manual starting angle in one neutral card, with automatic selection and pause restoration in separate cards; runtime readiness remains in the menu bar. A shared screen-access card appears above the other Seamless Close cards only while access is missing or during a three-second confirmation after a detected grant. It remains available in Privacy & about for status and management. Authorized launches omit the main-page card; revocation restores it. The main view owns the cancellable confirmation task.

The shared root keeps a 204-point sidebar beside a 544-point detail column, for a 748-point width. A full-size content view and empty native unified toolbar let AppKit present the window controls over the sidebar with its toolbar-window corner geometry; the titlebar separator is hidden. Window height stays at 560 points, capped to the available screen, and is updated on display changes. Each page has an independent scroll-view identity, so navigation starts at the top. Shorter pages and permission-card changes do not resize the window. Detail pages use 24-point padding. Seamless Close keeps the current lid angle in the combined switch-and-angle card; the slider has no live-angle marker. Privacy & about shows the app name and version, privacy information, and separate access card. Hardware and alpha limitations remain in README and testing documentation.

The live lid-angle number rounds fractional readings to whole degrees before presentation-only stabilization: one-degree changes wait for 250 ms of continuous samples, while changes of at least two degrees appear immediately. Raw sensor readings still drive the gesture, automatic angle selection, and **Use current angle**. Seamless Close shows bundled still previews for Blur strength. Opening Settings does not start an effect or capture the desktop.

Buttons share hover and pressed feedback, with activation and cancellation owned by SwiftUI Button. Sidebar presses strengthen only the row fill, leaving icon and text opacity unchanged. The AppKit slider preserves system tracking and keyboard input with a solid-white thumb that changes size slightly on hover/press. The angle field includes a raised degree symbol and left-side arrow buttons, each with independent hover/pressed feedback and hold-to-repeat. The restored AppleSwitchStyle uses a 44 × 22-point capsule, a white 26 × 18-point thumb, the system accent, and a native Toggle accessibility representation. The slider adds no outer hover surface or border; arrow highlights stay inside their own hit areas. The angle field adds an editing outline. The settings window ends field editing on an outside mouse click before forwarding that same event, so other controls still respond on the first click. Feedback overlays do not intercept input, disabled controls suppress feedback, and transitions respect Reduce Motion.

Pause restoration uses the shared return-to-flat and fade-out path with a deformation-dependent 340–600 ms return and snapshot cancellation tokens. Its balanced return curve builds and releases speed gradually, then settles to zero with no overshoot; the final 50 ms fade still starts only once the image is flat. Only fresh sensor samples count toward the saved pause wait; the return cleanup watchdog operates after restoration has begun. The pause and automatic-angle toggles are stored in UserDefaults; the learned angle is session-only. Automatic selection places the threshold one degree below the rounded held angle. A restored gesture keeps the held angle as its reopening gate, so the lower threshold cannot rearm it during the same pause. Changing the pause toggle restarts tracking without clearing an already-restored gesture latch. Changing automatic selection cancels an active gesture and starts learning afresh. Editing the manual angle does not interrupt a gesture anchored to a learned angle. The app saves independent 0.5–10 second waits for pause restoration and automatic detection, with a one-second default for each. The pause card has a switch row and a separate wait control. The menu status reports when the desktop has been restored.
