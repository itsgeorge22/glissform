# Implementation notes

- **LidSensor.swift:** read-only IOKit HID access, Apple vendor/product `05ac:8104`, usage `0020:008a`, feature report 1. Whole-degree values are read on a serial worker at 30 Hz, with bounded reconnect backoff. Protocol support is undocumented.
- **ClosingMotion.swift:** gesture and threshold state, including awake reversal and startup/reset behavior. Optional pause restoration uses monotonic sensor timestamps, a one-degree min/max stability band, and a configurable 0.5–10 second wait. Movement beyond that band resets the clock, as do invalid readings or gaps over 250 ms. Expiry deactivates the gesture and latches suppression until the lid is strictly above the trigger. Lifecycle reset clears the clock and latch; low-angle startup remains unarmed.
- **DesktopCapture.swift:** one native-resolution sRGB ScreenCaptureKit screenshot per gesture, excluding Glissform itself. No stream is started. Pixels remain in memory.
- **ScreenProjection.swift / EffectRenderer.swift:** runtime-compiled Metal projection and frost/shadow, with a fixed viewpoint approximation. Camera distance is four screen heights and eye height 1.1 screen heights, relative to the reference image plane. Every physical degree maps to one rendered degree, with no 89° fold clamp. Frost uses a normalized 5×5 binomial (Gaussian-like) kernel over interpolated mip levels. Radius grows monotonically with displayed closing progress through `(1 - exp(-3p)) / (1 - exp(-3))`, establishing the diffuse material early. A smooth vertical gradient scales its maximum support radius from 1.5% of image height at the hinge to 9% at the top (kernel standard deviation is approximately half that radius), retaining more definition so the perspective remains visible. This is visual tuning against the supplied reference stills, not a reconstruction of their original shader or timing. Shadow strength follows `p^2.2`, retaining more colour through mid-closure while keeping the full-height gradient and final top 5% black plateau. Active rendering requests the display's maximum refresh rate and pauses once settled.
- **MotionSmoothing.swift:** exact critically damped filtering for quantized angles and 100 ms boundary handoffs. Velocity is retained when response time changes; reversals discard old-direction momentum. Averaged per-degree cadence selects the response smoothly, avoiding the former fast/slow switch between one- and two-degree reports. The usual 35 ms time constant shortens above 30 degrees/second and grows for sparse readings up to 100 ms; reversals and large discontinuities use 12.5 ms. Smoothing deliberately trades some tracking delay for steadier movement. No angles are extrapolated beyond the reported target.
- **main.swift:** menu controls, settings coordination, snapshot preparation/reveal, overlay ordering and click blocking, sensor/capture coordination, and cleanup across sleep, display changes, cancellation, and quit.
- **SettingsWindow.swift:** native SwiftUI settings interface hosted in an AppKit window, including live sensor and permission state, persisted animation controls, and concise privacy information.

The first screenshot frame is rendered while the window is transparent. An 80 ms fade reveals it; the 100 ms angle handoff begins on the first fade tick, retaining an identity first frame instead of waiting for the entire fade. Returning to flat precedes an 80 ms exit fade. Snapshot tokens and renderer transition generations reject stale asynchronous work. The capture-source interface permits lifecycle checks to resolve synthetic screenshots after cancellation without requesting screen access.

This is a frozen image viewed through a simulated moving panel. It does not track the viewer's head, intercept the lock screen, or keep the system awake.

The settings window opens directly on the experience page, with native controls and semantic system colors. The footer opens Privacy & About; a Back button (⌘[) returns to the experience. There is no shared logo header or segmented navigation. An original Canvas illustration projects synthetic screen contours and a MacBook lid in perspective; the illustration follows the live reading, but does not reproduce the Metal effect pixel for pixel. SettingsModel synchronizes trigger controls, enable state, live angle, permission, and runtime status. The preview card groups the illustration and threshold controls, separated by a divider. A separate pause-to-resume settings card follows below it; runtime readiness remains in the menu bar and screen-access management in About. The current angle remains above the illustration; the slider has no live-angle marker. Preview and pause settings cards share a background, corner radius, and border, with a 16-point gap. The privacy footer has reserved bottom padding. Privacy and alpha limitations live in About, also opened by the standard About Glissform menu command.

The in-window preview has local observable state and a finite SwiftUI task. It snapshots the displayed lid angle and reference plane when playback starts, then immediately begins a synthetic close/reopen cycle back to that angle, without an opening hold. Its closing target is 22° or the starting angle if already lower, so starting the preview never first opens a nearly closed illustration. It stops on request or navigation away, and never calls DesktopCapture or the overlay renderer. Reduce Motion replaces playback with a still preview and disables interpolation of the live illustration. All content surfaces are opaque and adapt to system appearance; controls use the system accent. These accessibility changes apply to the settings illustration, not to the actual desktop effect.

Settings buttons share a ButtonStyle for hover and pressed feedback; activation and cancellation remain owned by SwiftUI Button. The AppKit slider preserves system tracking and keyboard input with a solid-white thumb that changes size slightly on hover/press. The angle field includes a raised degree symbol and left-side arrow buttons, each with independent hover/pressed feedback and hold-to-repeat. A SwiftUI capsule switch keeps its thumb solid white, applies hover/press feedback to the track, matches the System Settings proportions, uses Button for activation, and exposes a native Toggle accessibility representation. The slider and switch add no outer hover surface or border; arrow highlights stay inside their own hit areas. The angle field adds an editing outline. The settings window ends field editing on an outside mouse click before forwarding that same event, so other controls still respond on the first click. Feedback overlays do not intercept input, disabled controls suppress feedback, and transitions respect Reduce Motion.

Pause restoration uses the existing return-to-flat and fade-out path, including snapshot cancellation tokens. No independent timeout can fire while sensor delivery is absent. The two pause preferences are stored locally in UserDefaults; changing either restarts tracking without clearing an already-restored gesture latch. The settings status explains when the desktop has been restored and how to rearm.
